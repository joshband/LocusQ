# Backlog Summary Schema Contract

## Purpose

Define a stable, machine-readable contract for backlog summary exports so non-technical humans, scripts, and coding agents can consume one reliable data shape.

## Canonical Artifacts

- `Documentation/reports/data/backlog-summary.json`
- `Documentation/reports/data/backlog-summary.csv`

Generated by:
- `./scripts/export-backlog-summaries.py`

## Refresh Contract

1. Backlog changes under `Documentation/backlog/**` trigger auto-refresh in `.githooks/pre-commit`.
2. Manual refresh remains available:
   - `./scripts/export-backlog-summaries.py`
3. Freshness gate check:
   - `./scripts/export-backlog-summaries.py --check`
   - (also enforced by `./scripts/validate-docs-freshness.sh`)

## JSON Top-Level Contract (`locusq-backlog-summary-v1`)

| Field | Type | Rule |
|---|---|---|
| `schema_version` | string | Must equal `locusq-backlog-summary-v1`. |
| `source` | string | Must equal `Documentation/backlog`. |
| `counts` | object | Includes `total`, `open`, and `done` integer counts. |
| `items` | array | Ordered backlog item objects sorted by `id` (or path fallback). |

`counts` object fields:
- `total`: total number of exported runbooks.
- `open`: number of runbooks under `Documentation/backlog/` (excluding `done/`).
- `done`: number of runbooks under `Documentation/backlog/done/`.

## JSON Item Contract

Each `items[]` object uses this shape:

| Field | Type | Rule |
|---|---|---|
| `id` | string | Backlog ID token (for example `BL-038`, `HX-06`). |
| `title` | string | Runbook title parsed from first `#` heading. |
| `state_bucket` | string | `open` or `done` based on path. |
| `status` | string | Status value from `## Status Ledger` table. |
| `priority` | string | Priority value from `## Status Ledger`. |
| `track` | string | Track value from `## Status Ledger`. |
| `depends_on` | string | Depends On value from `## Status Ledger`. |
| `blocks` | string | Blocks value from `## Status Ledger`. |
| `who` | string | `6W` answer for who. |
| `what` | string | `6W` answer for what. |
| `why` | string | `6W` answer for why. |
| `how` | string | `6W` answer for how. |
| `when` | string | `6W` answer for when. |
| `where` | string | `6W` answer for where. |
| `plain_language_summary` | string | First narrative paragraph from `## Plain-Language Summary`. |
| `objective` | string | First narrative paragraph from `## Objective`. |
| `runbook_path` | string | Repo-relative markdown path of the runbook. |

## CSV Contract

`Documentation/reports/data/backlog-summary.csv` is a flattened export of the same item fields, preserving this header order:

`id,title,state_bucket,status,priority,track,depends_on,blocks,who,what,why,how,when,where,plain_language_summary,objective,runbook_path`

## Versioning and Compatibility

1. Backward-incompatible schema changes require a new `schema_version` value.
2. Additive fields may be introduced in a future minor contract update when existing fields remain stable.
3. Consumers must gate logic on `schema_version` and fail closed on unknown major versions.

## Consumer Guidance

1. Prefer `id` as primary key.
2. Use `runbook_path` as deterministic fallback key when `id` is temporarily missing.
3. Treat empty strings as "not specified yet" (not parser failure).
